## 修配置子页面滚不动（/investigations/:name/config）

现象：「技能与指导」内容在底部被挡住，滚轮完全没反应。

实测数据（1440×900）：`#root` 高 757 且 `overflow: hidden`；`.subpage-app` 撑到 1347，
自身 `scrollHeight === clientHeight`（等于没溢出，`overflow-y:auto` 永远不触发）；
滚轮后 `scrollTop` 还是 0。

根因是两层高度没接上：
1. `.subpage-app` 只写了 `min-height: 100vh`，没有约束高度 → 被内容撑开；
2. 更隐蔽的一层：antd `<App>` 会在 `#root` 和页面之间插一个 `div.ant-app`，
   它默认高度由内容撑开。所以就算给 `.subpage-app` 写 `height: 100%`，
   百分比也没有可解析的父高度，仍然等于 auto。

改法（`web/src/styles.css`）：`#root > .ant-app { height: 100% }` +
`.subpage-app { height: 100%; overflow-y: auto }`。顶栏 `position: sticky` 因此正常吸顶。

顺带修：`InvestigationConfigPage.tsx` 里技能卡片复用了弹窗的 `.selected-skill`
（`display:flex; justify-content:space-between`），把 antd Card 的标题和正文挤成左右两栏。
改名成 `.skill-card`，弹窗那份 CSS 保持不动。

验证：headless Chrome 走完 5 个页签 + Agent 轨迹页，19/19 通过
（每页滚动容器 clientHeight === 视口高、滚到底最后一块内容可见、顶栏吸顶 top=0）；
聊天主界面 `.app-shell` 仍 757，未被 `#root > .ant-app` 影响。

## 工作地图：自环连线看起来像断线（已修）

用户报「"设计新方案" 明显有节点没连接，为什么不标红？」。

查下来不是检测漏了，是画法问题。`needs-input -> 同一步骤` 这种自环，
`getSmoothStepPath` 会从右侧出口出去、再在同一高度原路折返回左侧入口。
折返段跟节点卡片一样高，被卡片整个盖住；屏幕上只剩左右两截各约 20px 的悬空短线，
看着像"连了个不存在的节点"。

证据：`target:needs-input:target:1` 的 `d` 是
`M1038.19 136.17 L1058.19 136.17 L847.25 136.17 L867.25 136.17`，
`getBBox()` 高度 = **0**。`intake`/`data-truth`/`investigate` 的自环高度只有 15~38，同样落在卡片里。
节点 in/out 度都 ≥ 1，服务端 `POST /workflow/validate` 返回 `{"issues": []}`，所以不标红是对的。

改法（`web/src/components/JourneyMap.tsx`）：新增 `selfLoopPath()`，
自环改成「右出口 → 绕到节点下方 → 左入口」，用 `useInternalNode(source)` 取
`internals.positionAbsolute.y + measured.height` 定位节点底边。修完 bbox 高度 93~146，
编辑模式和锁定模式都实测可见。

## 工作地图：带草稿进编辑模式，画布画的是已应用版本（未修，待定）

`JourneyMap.tsx` 里有两处都会重建画布：
- `loadWorkflow()`（`editing` 变化时触发）——**永远用 `data.definition`（已应用版本）**；
- `useEffect([editing, usingDraft, snapshot?.version])` 里的 `initializeGraph()`——会用 `draft.definition`。

后者先跑完，前者带 `await fetch` 后跑完并覆盖，结果画布永远是已应用版本。

实测（造一个带孤立节点的草稿）：顶部"已载入之前保存的草稿"横幅出现、
校验面板列出 17 条问题（含 `target 没有任何出口`、`orphan 没有任何出口`），
但画布始终 13 个节点、没有 `orphan`、没有任何节点带 `journey-flow-node-connection-error`。
即"画布和校验面板互相矛盾"，草稿里断开的节点根本画不出来，自然也不可能标红。

修法方向：把 `loadWorkflow` 里的建图那段删掉，只留 fetch + `setSnapshot`，
让唯一那个区分 draft/locked 的 effect 负责建图。

## 工作地图：带草稿进编辑模式（已修，覆盖上面那条"未修"）

改法：
1. `loadWorkflow()` 只做 fetch + `setSnapshot`，把 409 分支里的 `setNodes([])/setEdges([])` 也去掉；
2. 原来那个只服务编辑模式的 effect 改成**画布的唯一重建入口**，锁定/编辑都走它，
   来源按 `editing && usingDraft && snapshot.draft` 选草稿还是已应用版本；
3. 用 `graphKey` 当 effect 依赖，而不是 `snapshot` 对象：
   `[snapshot.source, version, edit|lock, draft|active, 节点 id + 出口数签名].join('#')`。
   这样"保存草稿"（对象换了、内容没换）不会重建画布，撤销栈 / 选中状态 / 当前视角都留得住；
   而"恢复内置"不改版本号，靠那份内容签名认出来。
4. effect 内部从 `snapshotRef.current` 取快照——`snapshotRef` 那个 effect 声明在前面，
   同一次 commit 里先跑，所以拿到的就是最新值。

**注意别用 ref 挡重入**（`if (key === ref.current) return`）：`web/src/main.tsx` 开着
`React.StrictMode`，挂载时 effect 会 setup → cleanup → setup，
第二次 setup 会被自己的 ref 挡掉，而第一次的 `await layoutWithElk` 又被 cleanup 的
`cancelled` 掐死 → 画布空白。用 state/派生值当依赖才不会踩这个坑。

验证（11/11 + 9/9，headless Chrome）：
- 锁定模式 = 已应用版本（13 节点、不标红）；
- 带坏草稿进编辑模式 = 草稿（14 节点含 `orphan`），`target`/`mapping`/`orphan` 都带上
  `journey-flow-node-connection-error`，和校验面板的 17 条问题对得上；
- 保存草稿后节点和视角都不变；
- 取消编辑回到已应用版本；
- 无草稿的 session 进出编辑模式，图完全一致（没回归）；
- 合法草稿走"应用修改"→ 版本号涨到 v2、草稿横幅消失、画布换成新版本。

## 工作地图白屏（已修）——JourneyMap 重构成 hook 之后丢了 ReactFlowProvider

`JourneyMap.tsx` 被拆成 `useJourneyWorkflowEditor.ts` + `journey-map-*.ts` 之后，
`useJourneyWorkflowEditor()` 仍然在 `JourneyMap` 里调用，而 `JourneyMap` 正是渲染
`<ReactFlow>` 的那个组件。`<ReactFlow>` 只给**子节点**提供 store，管不到自己所在的组件，
所以 hook 里的 `useNodesInitialized` 抛：

```
Error: Seems like you have not used ReactFlowProvider as an ancestor.
    at useNodesInitialized (@xyflow/react)
    at useJourneyWorkflowEditor (useJourneyWorkflowEditor.ts:129)
    at JourneyMap (JourneyMap.tsx:69)
```

React 没有 error boundary → 卸载整棵树 → `#root` 子节点数为 0，整个页面白屏。

修法：`JourneyMap` 只负责套 `<ReactFlowProvider>`，真正的内容挪到内层
`JourneyMapCanvas`，hook 在内层调。

同一轮还修了三个连带问题：

1. **fitView 时机**：`setNodes(...)` 之后 `requestAnimationFrame(fitView)` 量到的还是空画布，
   算出来的缩放被 `maxZoom` 卡死 → 13 个节点只有 1~2 个在屏幕上。
   改成"置 `pendingFitRef` 标记 → 等 `nodesInitialized` 且 `nodes` 变了再对准"。
2. **实测重排 effect 的依赖**：原来依赖 `[editing, nodesInitialized, nodes.length]`。
   切编辑模式那次渲染里 `nodes` 还是旧的一批，它拿着旧节点去排版、结果比重建画布回来得晚，
   把刚建好的草稿（14 节点）盖回 13 节点。改成依赖 `[nodes, nodesInitialized]`，
   `editing` 只在函数体里当开关。
3. **graphKey 的内容签名要排序**：服务端保存后返回的 definition 里节点顺序和画布顺序不一样，
   `nodes.map(id+routes.length).join('|')` 会因此变化 → "保存草稿"被当成内容变了 →
   画布重建 + 视角重置。加 `.sort()` 即可。

另外把 `<ReactFlow fitView fitViewOptions={...}>` 两个 prop 删了：prop 的 `fitViewOptions`
会覆盖 store 里的同名值，导致实例 `fitView({minZoom:0.45})` 实际按 prop 的 0.4 算。
现在视角只由 hook 一处负责。

验证：`draftfix.mjs` 11/11、`applycheck.mjs` 9/9、`fitcheck.mjs` 5 条自环 bbox 高度 135~146、
`whiteprobe.mjs` 两个 session 都无异常。typecheck / flow:lint / 74 个 TS 测试 / build 全过。

**遗留（未动，等用户定）**：`fitView` 的 `minZoom: 0.45` 是"可读优先"的下限，
而这个 Workflow 的 ELK 布局宽 3498、高 997，要塞进 1258×736 的画布需要 0.295。
所以打开地图是 9/13 可见，右边 4 个要平移。这是当初刻意的取舍，没擅自改。

## 踩坑：复用旧 scratch session 会让"版本号 +1"的断言假失败
