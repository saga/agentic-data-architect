# 1. 先看研究领域到了什么程度

最值得关注的一篇总览是 2026 年的 **Data Agents: Levels, State of the Art, and Open Problems**。

论文把 Data Agent 分成 L0–L5：从没有自治能力的工具，到真正能够主动发现问题、规划和执行完整数据工作流的自治数据科学家。作者认为现有大量产品仍集中在 L0–L2，而能够端到端编排复杂数据工作流、但仍有监督的系统属于 Proto-L3；L4/L5 仍主要属于研究方向。([arXiv][1])

这对你的项目很重要，因为它说明：

**“Data Agent”这个词现在很宽，但真正的 enterprise-grade autonomous Data Architect 其实还没有成熟。**

另一个 2025 年综述 **LLM/Agent-as-Data-Analyst: A Survey** 把核心设计方向概括为：

* semantic-aware
* heterogeneous/multi-modal
* autonomous pipeline
* tool-augmented
* open-world

这和你希望 Agent 同时读 DB、SQL、ETL、文档、BI、业务定义的目标高度吻合。([arXiv][2])

# 2. 最相关的研究论文

我会把论文分成 4 组，而不是把所有“LLM+数据”的论文混在一起。

## A. Data Agent / Data Analyst

### 1. Data Agents: Levels, State of the Art, and Open Problems

**2026，Luo / Li / Fan / Tang**

([arXiv][1])

这是目前最值得你读的一篇总览。

它的价值不是某个具体算法，而是给了一个很好的系统分层：

```text
L0 Tool
L1 Assistant
L2 Agent
L3 Proto-autonomous Agent
L4 Proactive Agent
L5 Generative / Autonomous Data Scientist
```

### 对你的启发

你的目标显然不是：

```text
NL → SQL
```

而更接近：

```text
Question
→ inspect environment
→ discover data
→ inspect dependencies
→ formulate hypotheses
→ execute analysis
→ infer business rules
→ design architecture
→ validate
```

也就是 Proto-L3 往 L4 方向走。

### 局限

论文主要讨论 Data Agent，不是专门针对：

* legacy ETL
* data architecture
* migration
* source-to-target mapping
* financial data

所以它解决的是 **Agent 能做什么**，没有解决 **企业数据架构 Agent 应该怎么落地**。

## 3. DAgent: A Relational Database-Driven Data Analysis Report Generation Agent

2025。

这个项目非常适合研究 **Data Analyst Agent**。


### 优点

* cross-table analysis

> “这个数据库为什么这样设计、这个数据是怎么产生的、这个业务规则藏在哪里、应该如何重构？”

所以 DAgent 是你的 **Analyst 子系统参考**，不是完整产品参考。

# 4. 最值得你的项目直接借鉴的论文：AgentModernize

这个是目前和你想做的东西最接近的研究。

## AgentModernize: Preserving Business Logic in Legacy Modernization with Multi-Agent LLMs and Behavioral Specification Graphs

2026。

([arXiv][7])

GitHub：

([GitHub][8])

它的核心不是：

```text
COBOL → Java
```

而是：

```text
Legacy
 ↓
Business Rule Extraction
 ↓
Behavioral Specification Graph
 ↓
Code Generation
 ↓
Equivalence Validation
```

也就是说：

> **先把 legacy 的“行为”显式化，再生成新系统。**

它的 BSG（Behavioral Specification Graph）是整个方案的 trust boundary。

论文评估了 8 个 legacy modernization 场景，包含 telecom 和 banking；四个 Agent 分别承担 extraction、specification、generation、validation。论文报告 BSG 能捕获 91.2% 的 gold rules，但最终代码生成仍然是瓶颈。([arXiv][7])

### 这个思想非常值得你吸收

我甚至建议你直接借鉴其核心思想，但把 BSG 扩展成：

```text
Evidence Graph
```

里面不仅有：

```text
Business Rule
```

还应该有：

```text
Table
Column
Source
Transformation
Lineage
Metric
Business Concept
Decision
Assumption
Evidence
Validation
```

这样就从：

> Legacy Application Modernization

扩展成：

> **Enterprise Data Architecture Modernization**

这是两个层次。

# 37. 最终判断

研究下来，我对这个项目的判断比上一轮更明确：

**这个方向值得做，而且存在明显空档。**

但这个空档不是：

> “还没有 AI Data Analyst。”

这个已经有很多。

也不是：

> “还没有 AI migration tool。”

商业市场已经有几个很强的玩家。

真正的缺口是：

> **一个 vendor-neutral、evidence-first、domain-aware 的 AI Data Architect，能够把 heterogeneous legacy data estate 反向还原成一个可验证的 current-state model，再进一步做 target-state architecture、source-to-target mapping、migration specification 和 validation。**

特别是：

```text
Financial Services
+
Investment Research
+
Portfolio Management
```

这个组合目前没有看到一个开源项目真正把它做完整。

### 我认为最值得重点研究的组合

**研究论文**

1. **Data Agents: Levels, State of the Art, and Open Problems** — 建立 Agent 能力分层。([arXiv][1])
2. **LLM/Agent-as-Data-Analyst: A Survey** — Analyst Agent 技术全景。([arXiv][2])
3. **Data Agent: A Holistic Architecture...** — Agent 系统架构。([arXiv][3])
4. **DeepAnalyze** — autonomous data science。([arXiv][5])
5. **DAgent** — multi-step relational data analysis。([arXiv][4])
6. **Can LLMs Clean Up Your Mess?** — data cleaning/integration/profiling。([arXiv][6])
7. **AgentModernize** — legacy business-logic preservation。([arXiv][7])

**开源**

