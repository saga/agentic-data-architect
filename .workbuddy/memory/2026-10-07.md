四路并行只读审查 + 主 agent 复核。基线：`npm test` 182 个测试全过，但下面 3 条严重问题都在测试覆盖盲区里。

### 严重（已实测复现）

**1. `validateLocalReadOnlySql` 返回被破坏的 SQL**（`src/analytics/local-data.ts:454-483`）
函数把注释和字符串字面量替换成空格后返回的是 `sanitized` 而不是原始 `sql`。所有下游（`:873` explain、`:908` transform、`:982` exportParquet、`:1043` query）执行的都是引号被挖空的 SQL。实测：
- `SELECT a FROM raw.t WHERE name = 'Alice'` → `SELECT a FROM raw.t WHERE name =`（语法错）
- `SELECT 1 /* delete from x */ FROM raw.t` → `SELECT 1 / FROM raw.t`（单斜杠，块注释正则 `\*[\s\S]*?\*\/` 被前面的 `/*` 消耗后错位）
- 危险的是静默错误：字面量被挖空后可能构成合法 SQL，查到别的数据并被 `appendInvestigationEvidence` 写成 Evidence。
- 测试为什么没抓到：`tests/local-data.test.ts:18-35` 四个用例都不含引号，「原样返回」恰好成立。
- 修法：改成纯谓词（返回 void），调用方继续用原始 `sql`；去尾分号只对 `sql` 做。

**2. `.workspace/copilot` 同时是 SDK baseDirectory 和一个合法 session**（`src/agent/copilot.ts:56` vs `src/investigation/workspace.ts:32`）
`copilotBaseDirectory = path.join(config.workspaceDir, 'copilot')`，而 `workspaceRoot(name)` = `path.join(config.workspaceDir, safeName(name))`。`listSessions`（`src/server.ts:215`）只排除 `shared`，所以 `.workspace/copilot` 会被当成名叫 `copilot` 的调查列出，且 `investigationExists('copilot')` 恒为 true → 用户既建不了也删不了这个 session。
实测该目录 **214M**：`artifacts/` 177M（2124 条 evidence 的真实调查）、`graphify-out/` 29M、`session-state/` 2.7M、`context.json` 1.9M。对照正常 session `研究IBM的sample项目数据架构` 只有 124K。
`local-data.ts:358` 的 discover skip 列表里已经有 `'copilot'`，说明问题被感知过但没在布局层解决。
修法：SDK baseDirectory 移到 `config.dataDir` 下；`listSessions` 改白名单过滤（含 `context.json` 且 `context.name === 目录名`）。

**3. `withWorkspaceContextLock` 不可重入 + 锁内做 LLM**（`src/investigation/workspace.ts:89-106`）
锁没有 owner token，嵌套调用时内层 `await previous` 永远等不到外层 release → 永久挂起。同样的模式在 `withSharedIndexWriteLock`（`:55`）和 `withControlUpdateLock`（`src/investigation/control.ts:39`）各复制一份。
`runReport`（`src/workflow/report.ts:153`）持锁后在 `:193` 调 `reviewArtifact` → `src/analysis/reviewer.ts:184,187` 最多两轮 LLM 往返，锁被持有数分钟；期间所有 `appendContextInput` / `saveInvestigation` / `appendInvestigationEvidence` / `getJourneySnapshot` 排队，用户在 UI 上保存工作地图会长时间转圈。
目前没死锁是靠调用顺序侥幸：`assessment.ts:112` / `modernization.ts:373` 都在 `journey-editor.ts:968` 取锁之前完成。一次重构就会永久挂起。
修法：加 owner token 支持重入；把 LLM 调用移出锁区间，锁只保护「读快照 → 计算 → 原子写」。
