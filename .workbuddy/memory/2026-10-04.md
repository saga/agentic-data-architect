三个独立原因，按影响排序：

1. **节点卡片基础样式整体缺失**：`web/src/styles.css` 里已经没有 `.journey-flow-node` / `-content` / `-title` / `-subtitle` / `-kicker` / `-config` / `.journey-flow-handle` / `.journey-flow-edge` 的基础规则，只剩 `-new` / `-current` / `-connection-*` 修饰规则。

   - `JourneyMap.tsx` 里设的 `--xy-node-background-color-default` 等变量对自定义节点类型 `journey` 无效（React Flow 只在内置 `-default/-input/-output/-group` 用这些变量）。

2. **`<ReactFlow>` 没传 `minZoom`，默认 0.5 把 fitView 的结果抬回去**：`@xyflow/system` 里 panzoom 用 `d3Zoom.scaleExtent([minZoom, maxZoom])`，`fitView()` 的 viewport 也走 `d3Zoom.transform`，所以传给 `fitView({minZoom: 0.2})` 没用。
   - 该 workflow 展开后约 3624×791 CSS px，画布约 1250 CSS px → 需要 ≈0.29，被抬到 0.5 → 右侧约 1/3 内容（3~4 个节点）被 canvas 裁掉且够不到。
   - 之前 `5d6e9d8` / `45da415` 删的是自家代码里的 zoom floor，组件级默认 floor 还在。

3. **布局是斜向阶梯**：`enforceWorkflowReadingOrder` 只按 rank 重写 x（0/308/616…），y 原样沿用 ELK 结果。ELK 面对 6 条回边（retry / needs-input / rollback）断环后列序与流程顺序不一致（实测 x = 1336,1652,1968,1652,1968,80,396,712,1020,1336,1652,1968），于是 y = 583,583,548,319,159,125,90,60,60,30,0,7 一路斜上去。
   - 回边不进布局，被画成横跨 2~8 层的长线，标签飘在离节点很远的位置。
